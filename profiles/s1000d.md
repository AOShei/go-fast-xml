# Profile `s1000d`

S1000D data modules (`dmodule`), publication modules (`pm`) and data
management lists (`dml`), issues 4.x, no namespace.

## Selection

Root element `dmodule`, `pm` or `dml` in no namespace.
`Extra["s1000d.module"]` records which.

## Mapping

| Element | Model |

| `dmAddress`, `pmAddress`, `dmlAddress` | `Extra["s1000d.ident"]`: the `dmIdent`/`pmIdent`/`dmlIdent` written as an outline of its elements and attributes, in the file's order: `dmCode(modelIdentCode=…, …), language(…), issueInfo(issueNumber=…, inWork=…)`. This is the data module code as written; it is not assembled into a `DMC-…` string (see "Needs") |
| `issueDate` (of the module) | `s1000d.issue_year`, `_month`, `_day` |
| `dmTitle`, `pmTitle` | `Metadata.Title` (`techName infoName`) and a level 1 heading where it stands |
| `dmStatus`, `pmStatus`, `dmlStatus` | `s1000d.status` (`issueType`), `s1000d.security_class` (`securityClassification` as declared), `s1000d.commercial_class`, `s1000d.caveat`, `s1000d.responsible_partner` (+`_code`), `s1000d.originator` (+`_code`), `s1000d.applic` (display text), `s1000d.applic_property_ident`/`_type`/`_values` (a single `assert`), `s1000d.applic_evaluate` (an `evaluate` as an outline), `s1000d.brex`, `s1000d.quality_assurance`, `s1000d.skill_level`, `s1000d.system_breakdown_code`, `s1000d.applic_cross_ref_table` (outlines), `s1000d.reason_for_update` (lines), `s1000d.restriction_instructions`, `s1000d.restriction_info`, `s1000d.tech_standard`, `s1000d.remarks` |

## Citing a block

Module: `s1000d.ident` (data module code, language and issue as
written). Block: `Loc.Anchor` (`para@id`, `levelledPara@id`, `figure@id`,
`table@id`) or `Attrs["anchor_parent"]`; a step's blocks carry the step id
in `s1000d.step`. `Loc.Offset`/`Length` give the bytes.

## Left to generic reading

Wiring and applicability cross-reference data (`electricalEquip*`,
`functionalPhysicalArea*`, `functionalItemRef`, `installationInfo`,
`applicCrossRefTable*`, `productDefinitionRelationship`), the learning
content (`lc*`), the common repository (`cautionRepository`,
`cautionSpec`), `proceduralStepAlts`, `if`/`elseIf`/`caseCond`,
`externalAssert`, a single `assert` inside a content `applic` (its
attributes become notes at their place), `configAttributes`. The empty
`noConds`, `noSupplies`, `noSpares`, `noSafety`, `noSupportEquips`
declarations make no block. Unmapped attributes include `issueDate` in
references, `changeType`/`changeMark`/`reasonForUpdateRefIds`, the
`xlink:*` of `dmRef`, `objectPath@allowedObjectFlag`, the
`s1000dSchemas` attributes.

## Versions

Dev samples (35): S1000D issue 4.1 (Bike sample data), 4.2 (Bike sample
data, s1kd-tools, kibook CSDB, including the S1000D default BREX). Not
covered: issues 5.0 and 6, issue 4.0.x, and the content kinds the samples
lack: fault isolation, IPD, schedule, process, container, SCO, checklist,
wiring fields.
